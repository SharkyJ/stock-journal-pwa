# 전망 리포트 공통 규칙

`outlook-daily`, `outlook-weekly` 스킬이 함께 따르는 규칙이다. 설계: `docs/outlook-pipeline.md`.

## 실행 위치와 파일

- 레포 루트에서 실행한다. 스크립트는 `ops/outlook/`에 있고 표준 라이브러리만 쓴다(설치 없음).
- 작업 파일은 `ops/outlook/work/`에만 쓴다(커밋 대상 아님). 시작할 때 `rm -rf ops/outlook/work && mkdir -p ops/outlook/work`.
- 스크립트 종료 코드: `0` 통과, `1` 재작성·재시도 필요(출력된 errors 를 고친다), `2` 중단.

## 역할 분담 (가장 중요)

- **수치는 만들지 않는다.** 지수, 가격, 등락률, 이동평균, 고저점, PER, 추정치 변화는 `market.json` 값만 쓴다. 웹 검색에서 본 수치는 `extra_sources.json`의 `values`에 기록한 경우에만 인용할 수 있다.
- 본문에 쓴 숫자는 그 행의 `nums`(market.json·extra_sources.json ID) 또는 `src`(뉴스·보완 출처 ID)의 값이어야 한다. 반올림은 허용하지만 다른 숫자는 검증에서 실패한다.
- **URL은 쓰지 않는다.** 출처는 `src`에 ID(N.., W..)로만 적는다. URL은 코드가 채운다.
- 대략적인 숫자(예: "5000선")를 지어내지 말고, 필요하면 `market.json`의 고저점·이동평균 값을 쓴다.
- **날짜도 근거가 있어야 한다.** 본문의 날짜(`11/12`, `11월 12일`, `2026-11-12`)와 시기(`1월 말`, `12월 중순`)는 그 행이 `nums`·`src`로 인용한 자료(시세 시각, `next_earnings`, 기사 제목·발행일, 보완 출처의 `values`)나 입력의 앱 신호 날짜에 있어야 한다. 근거가 없으면 쓰지 않는다. 일정이 필요하면 S3에서 찾아 `extra_sources.json`의 `values`에 날짜를 넣고 인용한다.
- `status`가 `ok`가 아닌 값(`stale`, `mismatch`, `unavailable`)을 인용하면 본문에 `확인 못 함` 또는 기준 시각(예: `16:46 기준`)을 적는다. `unavailable` 값은 인용하지 않는다.

## 웹 검색 (S3) 용도 제한

- 허용: 오늘(주간은 이번 주) 경제지표·정책 일정, 실적 발표일, 코스피200 야간선물(일간), 뉴스 맥락 보완.
- 검색은 10회 이내로 한다. 검색 결과 페이지를 추가로 여는 것(WebFetch)은 꼭 필요한 값(야간선물 등)에 한해 5회 이내로 한다.
- 결과는 `ops/outlook/work/extra_sources.json`에 기록한다.

```json
{"items": [
  {"id": "W1", "url": "https://...", "title": "기사·자료 제목", "kind": "event",
   "values": {"cpi_consensus_pct": 3.1}},
  {"id": "W2", "url": "https://...", "title": "...", "kind": "night_futures",
   "values": {"close": 702.35, "prev_close": 698.10, "as_of": "2026-11-10T06:00+09:00", "chg_pct": 0.61}}
]}
```

- `kind`: `event`, `earnings`, `night_futures`, `other`.
- `night_futures`는 `close`(야간장 마감가)와 `prev_close`(직전 주간장 종가)를 숫자로 넣는다. 등락률은 코드가 다시 계산하고, 출처 표시값(`chg_pct`)과 0.3%p 넘게 다르면 요약에 자동 표기된다. 직전 주간 종가를 찾지 못하면 `close`와 출처에 표시된 등락률 `chg_pct`만 넣는다(요약에 "직전 주간 종가 확인 못 함, 출처 표시 등락률"이 자동 표기된다). 이번 야간장 마감분인지 시각을 확인한다. 직전 저녁이 한국 휴장일이라 야간장이 없었으면 기록하지 않는다.
- `values`에는 출처에 실제로 적힌 숫자만 넣는다. 추정하거나 계산한 값은 넣지 않는다.
- 검색 결과가 없으면 `{"items": []}`로 둔다.

## 해석 체크리스트 (S4)

행마다 아래 관점을 확인한다. 모두 본문에 쓰라는 뜻이 아니며, 길이 제한 안에서 의미 있는 것만 쓴다. 데이터가 없는 관점은 건너뛰고 추정으로 채우지 않는다.

| 관점 | 확인 내용 | 근거 | 일간 | 주간 |
|---|---|---|---|---|
| 간밤·지수 흐름 | 미국 지수, 반도체 지수, 지수선물, 환율, 금리 방향 | market.json `indices`, `futures` | 필수 | 필수 |
| 가격 위치 | `vs_ma20_pct`·`vs_ma60_pct`·`vs_ma200_pct`, `hi20`·`lo20` | 종목 항목 | 필수 | 필수 |
| 컨센서스 변화 | `eps_rev_pct`(EPS 추정치 변화), `tgt_chg_pct`(목표주가 변화), `rec` | 종목 항목 | 변화가 ±2% 이상일 때 | 필수 |
| 밸류에이션 | `ntm_per` 또는 `fwd_per` 와 `per` 비교 | 종목 항목 | 선택 | 필수 |
| 이벤트 | 실적 발표일(`next_earnings` 또는 검색), 경제지표, 정책 일정 | market.json, news.json, extra_sources.json | 오늘 일정 | 이번 주·다음 실적일 |
| 앱 신호 정합성 | 최근 신호가 뉴스·가격 흐름과 맞는지. "앱 신호: 11/06 추세추종 매도·경계" 형식 | input.json `signals` | 최근 3거래일 | 최근 14일 |
| 레버리지 상품 | 기초자산(`under_id`) 기준으로 판단, 변동성 손실 위험 언급 | 기초자산 항목 | 필수 | 필수 |

## 작성 원칙

- 한국어, 짧고 사실 중심. 수치에는 기준 시점을 붙인다.
- 전망 값은 `강세`, `약강세`, `중립`, `약약세`, `약세` 중 하나만 쓴다.
- 확정적인 매수·매도 권유를 하지 않는다(금지 표현은 `ops/outlook/config.json`의 `forbidden`).
- 특별한 뉴스가 없으면 그렇게 쓴다.
- 오늘이 한국 또는 미국 증시 휴장일이면 시장 전체 행 요약에 적는다.

## 토큰 절약

- 시트는 필요한 범위만 한 번씩 읽는다. 같은 범위를 다시 읽지 않는다.
- `market.json`, `news.json`은 통째로 출력하지 말고 필요한 항목만 `python3 -c` 등으로 골라 본다.
- S4는 한 번에 `analysis.json`을 쓰고, S5 오류가 있으면 해당 행만 고친다.

## 개인 정보

- 보유 수량·평균단가·금액은 `input.json`과 검색어에 넣지 않는다.
- 시트 ID는 레포에 쓰지 않는다. 예약 작업 프롬프트로만 받는다.

## 시트 쓰기 (S6)

- 대상 시트 이름은 예약 작업 프롬프트의 `TARGET_SHEET`를 따른다. 그 시트 외에는 수정하지 않는다.
- 시트가 없으면 만들고 1행에 `rows.json`의 `header`를 쓴다.
- 순서: (1) A열 작성일이 오늘(`rows.json`의 `date`)인 행 삭제 (2) 작성일이 `delete_before`보다 이전인 행 삭제 (3) `rows.json`의 `rows`를 마지막 행 아래에 그대로 추가.
- 값은 가공하지 않고 그대로 쓴다. 가능하면 RAW 입력(자동 변환 없음)으로 쓴다.
- 행 삭제는 아래쪽 행부터 지워 행 번호가 밀리지 않게 한다.

## 기록 검증용 재조회 (S7)

- `readback.json`은 **커넥터가 돌려준 값을 그대로** 저장한다. `rows.json`이나 기록하려던 값으로 만들면 검증이 무의미해지므로 절대 그렇게 하지 않는다.
- 시트가 길면 전체 대신 다음 두 가지를 읽는다: (1) 1행(헤더)과 오늘 기록한 행 범위, (2) A열 전체. 저장 형식은 `{"values": [[헤더], [오늘 행], ...], "dates": [A열 값]}`.
- 응답이 길어도 요약하거나 다시 만들지 않는다. 범위를 줄여 다시 읽는다.

## 실패 처리

- S1 또는 S2 종료 코드 2: 시트에 쓰지 않고 중단한다. 출력된 error를 결과로 보고한다.
- S5 종료 코드 1: errors를 보고 `analysis.json`(또는 `extra_sources.json`)을 고친 뒤 1회만 다시 실행한다. 다시 1이면 시트에 쓰지 않고 중단, errors를 보고한다.
- S7 종료 코드 1: S6을 다시 수행한다(최대 2회). 그래도 실패하면 오늘 행을 지우고 중단, errors를 보고한다.
- 스크립트 결과를 확인하지 않고 성공으로 보고하지 않는다. S7이 0이어야 성공이다.
