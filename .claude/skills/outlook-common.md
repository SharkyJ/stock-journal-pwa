# 전망 리포트 공통 규칙

`outlook-daily`, `outlook-weekly` 스킬이 함께 따르는 규칙이다. 설계: `docs/outlook-pipeline.md`.

## 실행 위치와 파일

- 레포 루트에서 실행한다. 스크립트는 `ops/outlook/`에 있고 표준 라이브러리만 쓴다(설치 없음).
- 작업 파일은 `ops/outlook/work/`에만 쓴다(커밋 대상 아님). 단계 번호는 각 스킬(1~6단계)을 따른다.
- 스크립트 종료 코드: `0` 통과, `1` 재작성·재시도 필요(출력된 errors 를 고친다), `2` 중단.

## 역할 분담 (가장 중요)

- **코드가 만든다:** 입력(`prepare.py`), 수집(`collect.py`), 행별 초안 전망·사실 문장·체크포인트·인용 ID(`draft.py brief`), 합치기(`draft.py merge`), 검증(`build_rows.py`), 기록 계획·검증. 아래 해석 체크리스트의 수치 관점은 모두 코드가 사실 문장으로 쓴다.
- **세션이 쓴다:** 행별 `lead`(3~6문장 권장, 최대 8문장), 근거 뉴스 `src`(최대 4개), 필요할 때만 전망 `adjust ±1`과 `why`. 그 밖의 값은 쓰지 않는다.
- **수치는 표로 간다.** 코드가 행마다 지표 표(JSON)를 만들어 시트 마지막 열 `지표`에 기록하고, 앱이 가공 없이 표로 보여준다. 요약 열에는 lead와 서술형 사실(거시 기조, 앱 신호 정합성)만 들어간다.
- lead의 숫자·날짜는 작성 과제의 표(다른 행 표 포함)·뉴스 제목에 있는 값만 쓸 수 있다. 다른 값은 4단계 검증에서 거부된다.
- 요약 전체의 문장 수·글자 수 한도는 없다. lead 문장 수(최대 8)만 제한한다. 그보다 길면 표와 중복되거나 읽기 어려워지기 때문이다.
- **URL은 쓰지 않는다.** 출처는 `src`에 ID(N.., W..)로만 적는다. URL은 코드가 채운다.
- 뉴스 태그의 호재·악재 후보는 키워드 기반이다. 제목을 읽고 판단한다.

## 웹 검색 (2단계, 선택) 용도 제한

- 허용: 작성 과제에 근거가 부족한 행의 뉴스 맥락, 실적 발표일, 정책 일정. 경제 캘린더가 `ok`가 아닐 때 경제지표 일정. 코스피200 야간선물은 다루지 않는다.
- 검색 횟수는 각 스킬의 2단계 한도를 따른다. 결과는 `ops/outlook/work/extra_sources.json`에 기록한다.

```json
{"items": [
  {"id": "W1", "url": "https://...", "title": "기사·자료 제목", "kind": "event",
   "values": {"cpi_date": "2026-11-12"}}
]}
```

- `kind`: `event`, `earnings`, `other`. `values`에는 출처에 실제로 적힌 값만 넣는다.

## 해석 체크리스트 (코드가 채우는 관점)

| 관점 | 코드가 쓰는 내용 | 근거 | 일간 | 주간 |
|---|---|---|---|---|
| 간밤·지수 흐름 | 미국 지수, 반도체 지수, 지수선물, 환율, 금리 | market.json `indices`, `futures` | 시장 행 | 시장 행 |
| 가격 위치 | 20·60·200일선 대비, 20일 범위(지지·저항) | 종목 항목 | 필수 | 필수 |
| 컨센서스 변화 | EPS 추정치·목표주가 변화 | 종목 항목 | ±2% 이상일 때 | 필수 |
| 밸류에이션 | 선행 PER과 PER | 종목 항목 | 컨센서스 문장이 없을 때 | 필수 |
| 거시 기조·경제 일정 | 거시 기조, 고영향 지표 일정, 최근 발표 판정 | calendar.json (C..) | 오늘·내일 | 이번 주 |
| 이벤트 | 다음 실적일·컨센서스 EPS, 직전 분기 결과 | events.json (E..) | 필수 | 필수 |
| 앱 신호 정합성 | 신호와 가격 흐름 일치 여부, "앱 신호: 11/06 추세추종 매도·경계" | input.json `signals` | 최근 3거래일 | 최근 14일 |
| 레버리지 상품 | 기초자산 등락·추세, 변동성 손실 위험 | 기초자산 항목 | 필수 | 필수 |

전망 초안 점수(일간·주간 단기): 등락(기초자산 우선) ±1.5%/±4%, 20·60일선 위·아래, EPS 추정 변화 ±2%, 뉴스 후보 우세, 최근 앱 신호 방향, 시장 점수(±2 이상). 합계 +3 이상 강세, +1 이상 약강세, 0 중립, -1 이하 약약세, -3 이하 약세. 시장 행은 지수선물·반도체지수·VIX·거시 기조·시장 뉴스로 계산한다.

## 작성 원칙

- 한국어, 짧고 사실 중심. 수치에는 기준 시점을 붙인다.
- 전망 값은 `강세`, `약강세`, `중립`, `약약세`, `약세` 중 하나만 쓴다.
- 확정적인 매수·매도 권유를 하지 않는다(금지 표현은 `ops/outlook/config.json`의 `forbidden`).
- 특별한 뉴스가 없으면 그렇게 쓴다.
- 오늘이 한국 또는 미국 증시 휴장일이면 시장 전체 행 요약에 적는다.

## 토큰 절약

- 시트 읽기와 파일 쓰기는 각 스킬에 표시된 대로 한 턴에 병렬로 호출한다. 시트 응답 값은 보지 않는다(훅이 저장).
- `draft.py brief`의 작성 과제만 읽는다. `market.json`, `news.json`, `draft.json` 등 JSON 원본은 열지 않는다.
- `notes.json`은 한 번에 쓰고, 검증 오류가 있으면 해당 행만 Edit로 고친다.
- 진행 상황 설명이나 중간 요약을 출력하지 않는다.

## 개인 정보

- 보유 수량·평균단가·금액은 `input.json`과 검색어에 넣지 않는다.
- 시트 ID는 레포에 쓰지 않는다. 예약 작업 프롬프트로만 받는다.

## 시트 쓰기 (5단계)

- 쓰는 시트는 `TARGET_SHEET`(전망)와 `EVENTS_SHEET`(주요일정, 기본 `App_주요일정`) 두 개뿐이다.
- **시트 쓰기 보호 훅**(`.claude/hooks/sheets_guard.py`, `.claude/settings.json`)이 1단계(`prepare.py begin`)에서 입력 수집 단계로 켜지고(쓰기 전부 거부, 읽기 응답은 행 수만 표시), 4단계 통과 뒤 기록 단계로 바뀐다.
  - 쓰기는 자리표시자로만 한다: `append_values`·`update_values`의 values는 `[["@plan"]]`, 삭제는 `update_spreadsheet`의 requests `[{"@plan": "delete"}]`. 훅이 `plan.json`의 범위·값으로 바꿔 실행한다.
  - 다른 시트 쓰기, 값을 직접 넣은 쓰기, 헤더·삭제 전 추가, 같은 계획의 중복 실행은 훅이 거부한다. 기록 대상 시트를 만드는 `addSheet`만 그대로 허용한다.
  - 시트 호출의 입력과 응답 원문은 훅이 `ops/outlook/work/sheet_log.jsonl`에 남긴다. 기록 대상 시트의 큰 읽기 응답은 요약만 보인다.
- 지울 행·추가 위치·헤더 갱신은 `plan_write.py`가 훅 기록에서 계산한다. 세션이 행 번호를 계산하거나 응답을 파일로 옮기지 않는다.
- 전망 시트: 오늘 작성일 행과 보관 기간이 지난 행을 지우고 오늘 행을 추가한다. 마지막 열 `작성시각`은 코드가 채운다.
- 주요일정 시트: ID가 같고 버전이 다른 행만 지우고 다시 추가, 새 ID는 추가한다. **지난 기록은 지우지 않는다**(보유 종목을 전량 매도해도 남긴다).

## 기록 검증용 재조회 (6단계)

- 재조회 범위는 plan의 `readback`이다(모든 열). 응답은 훅이 원문을 저장하고 세션에는 요약만 보인다.
- `verify_written.py`는 훅 기록의 append 응답(`updatedRange`)과 추가 이후의 재조회 응답만 읽는다. 숫자·백분율·날짜 표시 형식 차이는 정규화해 비교한다.
- 응답을 파일로 만들거나 합성하지 않는다. 검증기가 읽지 않으므로 의미가 없다.

## 실패 처리

- 입력·수집(1단계) 종료 코드 2: 시트에 쓰지 않고 중단한다. 출력된 error를 결과로 보고한다. 종료 코드 1이면 `need`의 범위를 읽고 다시 실행한다.
- 합치기·검증(4단계) 종료 코드 1: errors를 보고 `notes.json`(또는 `extra_sources.json`)을 고친 뒤 1회만 다시 실행한다. 다시 1이면 시트에 쓰지 않고 중단, errors를 보고한다.
- 기록 계획(5단계) 종료 코드 1: 출력의 `need`대로 읽고 다시 실행한다. 종료 코드 2면 쓰지 않고 중단한다.
- 훅이 쓰기를 거부하면 사유대로 하고, 값을 직접 넣어 우회하지 않는다. 사유대로 할 수 없으면 중단하고 보고한다.
- 기록 검증(6단계) 종료 코드 1: 재조회 누락이면 6-1만, 값·위치 불일치면 5-1부터 다시(최대 2회). 그래도 실패하면 중단하고 errors를 보고한다.
- 스크립트 결과를 확인하지 않고 성공으로 보고하지 않는다. 6단계가 0이어야 성공이다.
