# 전망 리포트 개선 리팩터링 계획 (뉴스·캘린더·이벤트 반영)

일간·주간 전망 리포트(`ops/outlook`, `.claude/skills/outlook-*`)에 `docs/reference-news-calendar-events.md`의 출처와 로직을 적용하는 계획이다.

- 작성일: 2026-11-10
- 상태: 계획 (구현 전)
- 전제: `docs/outlook-pipeline.md`의 원칙 유지. 코드가 수집·계산·검증하고 LLM은 해석만 쓴다. API 키·추가 과금 없음, 표준 라이브러리만 사용, 시트 스키마(헤더·열) 불변.

## 1. 현황과 한계

| 영역 | 현재 | 한계 |
|---|---|---|
| 뉴스 출처 | Google News RSS 쿼리 2개(시장) + 종목당 1개, 최신순·중복 제거 | 연준 공식 발표가 없다. 기사 가치(호재·악재·관련도) 구분 없이 최신순이라 노이즈가 섞인다. 미국 종목은 `<코드> stock` 쿼리 하나뿐이다 |
| 뉴스 해석 | LLM이 제목만 보고 판단 | 같은 기사도 실행마다 판단이 흔들린다. 부정 표현("not", "despite") 처리 규칙이 없다 |
| 경제 일정 | S3에서 웹 검색 3~4회로 LLM이 찾는다 | 일정·수치가 실행마다 다르고 토큰이 든다. 발표 결과(서프라이즈)가 구조화되지 않는다 |
| 종목 이벤트 | Worker `/fund`의 `next_earnings`(미국·한국 일부) | 출처가 단일하고 실패하면 "확인 못 함"뿐이다. 보조 출처와 교차 검증이 없다 |
| 거시 기조 | 없음 | 최근 발표 지표가 전체로 호재·악재 어느 쪽인지 요약이 없다 |

## 2. 참고 문서에서 가져올 것과 버릴 것

참고 문서의 용도는 신규 매수 예산 조절이다. 이 프로젝트는 매매하지 않으므로 리스크 배수(`budgetMultiplier`)와 차단(`blocked`)은 버리고, **판정 로직을 "리포트 입력 신호"로 바꿔** 쓴다.

| 참고 로직 | 채택 | 적용 방식 |
|---|---|---|
| Fed 보도자료 RSS | 채택 | 통화정책 뉴스의 1차 출처. 시장 행의 근거로 인용 |
| TradingView 경제 캘린더(US) | 채택 | 일정·발표 수치의 결정적 출처. S3 웹 검색 대체 |
| 캘린더 `judgeBias`(서프라이즈 점수) | 채택 | 발표 지표를 호재·악재·혼조·예정으로 분류해 `calendar.json`에 기록 |
| 거시 기조 `summarizeMacroTone` | 채택 | 최근 5일 발표 합산 점수를 "호재 우위/악재 우위/중립"으로 제공 |
| Nasdaq 실적일 | 채택(보조) | 기존 `next_earnings`와 교차 검증. 컨센서스 EPS도 함께 수집 |
| 뉴스 렉시콘 감성(가중치·부정어 처리) | 채택(제한) | 점수는 **정렬·선별과 사전 태그**에만 쓴다. 최종 판단은 LLM이 하며, 본문에 점수를 수치로 인용하지 않는다 |
| 토픽·티커 태그, 관련성 판정 | 채택 | 기사 선별과 종목 매칭 정확도 향상 |
| `min(event, news, calendar)` 예산 배수, 하드 차단 구간 | 제외 | 매매 기능이 없다 |
| Yahoo Finance 헤드라인 RSS | 채택 | 2026-11-10 재시도 200(20건). 미국 종목당 2건, `news.yahoo_rss`로 끔. 실패 시 fail-open |
| 한글화(단어 치환·템플릿 요약) | 제외 | LLM이 한국어로 작성한다 |

공개 엔드포인트 응답 확인(2026-11-10, 이 세션 기준):

| 출처 | 결과 | 비고 |
|---|---|---|
| Fed `press_monetary.xml` | 200, 15건 | 정상 |
| TradingView 캘린더 | 200, JSON | 정상. 비공식이라 스펙 변경 가능 |
| Nasdaq `earnings-date` | 200 | **응답 형식이 참고 문서와 다르다.** `data.reportText`에 "estimated to report earnings on 12/16/2026"과 컨센서스 EPS 문장이 들어 있다. 문서의 `announcement` 문자열 정규식은 쓸 수 없으므로 `reportText` 기준으로 파서를 새로 쓴다 |
| Yahoo 종목 RSS | 200 (2026-11-10 재시도) | UA 없으면 404, 커스텀 UA는 정상 |

전용 환경 `stock-journal-outlook`의 허용 호스트는 현재 `sj-chart.blueinwhite.workers.dev`, `news.google.com`뿐이다. 새 출처는 환경 호스트 추가가 선행돼야 한다(3단계 R0).

## 3. 개선 방안

### A. 경제 캘린더 수집 (효과 최대)

- 신규 `ops/outlook/collect_calendar.py`: TradingView US 캘린더를 받아 `calendar.json` 생성.
  - 기간: 일간은 과거 4일~앞으로 2일, 주간은 과거 7일~앞으로 14일.
  - 정규화: `released`는 표시용 `actual`이 있을 때만, 수치는 `*Raw` 우선, importance -1 제외.
  - 판정: 참고 문서의 `judgeBias`를 그대로 이식(카테고리 가중치, magWeight, 양면 지표 혼조).
  - ID `C1..` 부여, 필드는 `title`, `time_kst`, `importance`, `actual`, `forecast`, `previous`, `bias`, `strength`, `score`.
- `collect.py` 요약에 `## 경제 일정` 절 추가. 발표 완료 지표(서프라이즈 포함)와 예정 고영향 지표를 분리 표시.
- 거시 기조 한 줄(`최근 5일 합산 +2.4 호재 우위`)을 요약 최상단에 둔다.
- 영향: S3 웹 검색에서 "경제지표 일정"을 빼 검색을 일간 3→2, 주간 4→2~3으로 줄인다. 일정 날짜는 `calendar.json`이 근거라 `build_rows.py`의 날짜 근거 검증이 `C..` 인용으로 통과한다.
- 한계 처리: 미국만 지원한다. 한국 지표(금통위, 수출입 등)는 계속 웹 검색 몫이다. 엔드포인트 실패 시 `calendar.json`을 `unavailable`로 쓰고 기존처럼 웹 검색으로 대체한다(fail-open).

### B. 뉴스 출처 확대와 선별

- 출처 추가: Fed 보도자료 RSS(`category: Fed`). 일간은 24시간, 주간은 14일 범위.
- Google News 쿼리 보강: 거시 쿼리를 `Federal Reserve OR FOMC OR inflation OR 반도체 OR AI`(참고 문서의 거시 기본어) 계열로 1개 추가하고 `-Bitcoin -crypto`를 붙여 노이즈를 줄인다. 기존 시장 쿼리 2개는 유지.
- 선별 로직 `ops/outlook/news_score.py`(신규, 순수 함수):
  - 렉시콘 점수: 키워드별 1회, 부정어(`no|not|without|avoid|unlikely|despite|less|lower`) 16자 이내면 무시, ±1.5 이상이면 호재·악재 후보. 렉시콘은 `config.json`에 두고 반도체·메모리 외에 이 포트폴리오(레버리지 ETF, 금융·에너지 보유분)에 맞게 조정.
  - 토픽 태그(연준, 금리, 인플레이션, 반도체, AI, 메모리, 무역, 레버리지)와 티커 태그(별칭 매칭).
  - 종목 관련도: 별칭·섹터 키워드(`config.json`의 `ticker_profiles`).
- 결과: `news.json` 항목에 `tags`, `sentiment_hint`(호재/악재/중립 후보)를 추가. 요약 출력은 `[연준·악재후보]` 같은 접두로 표시. 기사 수 상한(시장 5건, 종목 3건)은 유지하되 **점수 절댓값이 큰 기사를 우선** 남겨 같은 토큰 예산에서 정보량을 높인다.
- 사용 원칙: 감성은 힌트다. 참고 문서도 오탐을 인정하고 매수 축소에만 썼다. 이 파이프라인에서는 `sentiment_hint`를 본문에 수치로 쓰지 못하게 하고, 기사 선별과 LLM의 주의 환기에만 쓴다.

### C. 종목 이벤트 교차 검증

- 신규 `ops/outlook/collect_events.py`: Nasdaq `earnings-date`를 `reportText` 기준으로 파싱해 `next_earnings`(날짜), `consensus_eps`, `estimated` 플래그를 얻는다.
  - 대상: 미국 상장 보유·관심 종목(ETF·레버리지 상품 제외, 기초자산 개별주는 포함). 순차 호출, 종목별 지연 0.3초, 한 실행 안에서만 캐시(예약 세션은 매번 새 컨테이너).
  - 결합: Worker `/fund`의 `next_earnings`와 비교. 둘이 같으면 `ok`, 다르면 `mismatch`로 두고 두 값을 모두 기록해 LLM이 "일정 불확실"로 쓰게 한다(`checks` 규칙과 동일).
- Nasdaq 날짜는 알고리즘 추정치(Zacks)일 수 있다. 값에 `estimated`를 붙이고 본문에는 "예상"으로 쓰게 한다.
- 이벤트 근접도 `events_near`: 실적 발표 D-3 이내면 요약에 `실적 임박` 접두. 일간 체크포인트에 일정이 반드시 들어가도록 `outlook-common.md` 체크리스트의 "이벤트" 행을 강화한다.

### D. 입력 신호의 구조화와 해석 가이드

- `collect.py` 요약에 우선순위 절 `## 오늘의 핵심 신호`를 추가한다. 코드가 규칙으로 뽑은 3~6줄(발표 지표 중 강한 악재·호재, 24시간 내 고영향 예정, 실적 D-3 이내 종목, 부정 뉴스 3건 이상 종목)이다. LLM이 긴 요약에서 놓치는 항목을 줄이고 "무엇을 먼저 쓸지" 판단을 일관되게 한다.
- `outlook-common.md` 체크리스트에 "거시 기조·경제 일정" 행을 추가한다(일간: 오늘 발표·직전 서프라이즈, 주간: 이번 주 고영향 일정 목록과 발표 결과).
- `build_rows.py`: `C..` ID를 `nums`로 인용할 수 있게 하고, 수치·날짜 근거 검증이 `calendar.json`을 포함하게 한다. `src`에 쓸 수 있는 출처에 Fed·캘린더 URL을 허용한다(캘린더는 URL 없이 `TradingView 캘린더` 라벨, 시트 출처 열에는 Fed·뉴스 URL만).

### E. 토큰과 안정성

- 요약 길이 예산: 새 절 추가로 입력이 늘어난다. 요약은 일간 기준 40줄 안쪽으로 제한한다(캘린더는 고영향·예정·발표 상위 10건, 뉴스는 점수 상위 선별). 측정 기준은 `docs/outlook-pipeline.md`의 토큰 표(일간 $0.87, 주간 $0.88)를 넘지 않는 것이다. 웹 검색 감소분(턴 1~2, 출력 감소)이 상쇄할 것으로 보지만 구현 후 측정한다.
- 모든 새 수집은 실패해도 리포트 생성을 막지 않는다(fail-open). 기존 `unavailable` 규칙과 같다. 모든 출처 실패 시에만 기존 종료 코드 규칙을 따른다.
- 외부 의존: 세 출처 모두 비공식·무키라 차단·스펙 변경 위험이 있다. 파서 단위 테스트에 응답 샘플 fixture를 두고, 응답 형식이 바뀌면 `unavailable`로 처리해 조용히 틀린 값을 내지 않게 한다.

## 4. 구현 단계

| 단계 | 내용 | 산출물 | 완료 기준 |
|---|---|---|---|
| R0 | 환경 준비: 전용 환경 `stock-journal-outlook`에 허용 호스트 추가 후 3개 출처 실접속 확인 | 호스트 추가 요청(SJ 승인 필요): `www.federalreserve.gov`, `economic-calendar.tradingview.com`, `api.nasdaq.com`, `feeds.finance.yahoo.com` (SJ 승인 2026-11-10) | 예약 환경에서 3개 모두 200 |
| R1 | 캘린더: `collect_calendar.py`, `judgeBias` 이식, 요약 절, 테스트 | 코드, fixture, 단위 테스트 | 11월 실데이터로 발표·예정 분류가 TradingView 화면과 일치 |
| R2 | 뉴스: Fed RSS, 쿼리 보강, `news_score.py`, 요약 표기, 테스트 | 코드, 렉시콘 `config.json` | 부정어 케이스, 중복, 점수 임계 테스트 통과. 샘플 일자 뉴스 선별 결과 수동 점검 |
| R3 | 이벤트: `collect_events.py`, `reportText` 파서, `/fund` 교차 검증, 근접도 | 코드, fixture(Nasdaq 응답) | 보유 미국 종목 전수 실적일 비교 결과 정리 |
| R4 | 통합: `collect.py` 요약 재구성(핵심 신호 절), `build_rows.py`의 `C..` 인용, 스킬·공통 규칙 갱신 | 스킬 2개, `outlook-common.md` | 단위 테스트 전체 통과, 로컬 모의 실행에서 `verify_written.py` 통과 |
| R5 | 예약 환경 수동 실행(일간·주간 각 1회), 이전 결과와 비교 | 시험 시트(`*_v2`가 아닌 별도 `_test`) | 아래 5절 평가 항목 충족, 토큰 한도 내 |
| R6 | 반영: 정기 실행에 적용, 문서 갱신(`docs/outlook-pipeline.md`, `ops/outlook/README.md`) | PR | 첫 정기 실행 성공 후 완료 처리 |

순서 의존: R0는 R1~R3 실접속 검증의 선행 조건이다. 코드·테스트는 fixture 기반이라 R0와 병행할 수 있다. R1 → R4가 효과가 가장 크므로 R2, R3보다 먼저 한다.

롤백: 기능별로 `config.json`에 `calendar.enabled`, `news.fed_rss`, `events.nasdaq` 플래그를 둔다. 끄면 기존 흐름과 같아진다. 스킬 변경은 PR 단위라 되돌릴 수 있다.

## 5. 평가 방법

| 항목 | 방법 | 기준 |
|---|---|---|
| 일정 정확도 | 일간 5일치 `calendar.json`과 실제 발표 일정 대조 | 고영향 지표 누락 0 |
| 일정 서술 일관성 | 같은 날짜 데이터로 일간 2회 실행, 일정 문장 비교 | 날짜·지표명 일치 |
| 뉴스 선별 품질 | 변경 전후 같은 날짜 기사 목록 비교(SJ 수동 평가) | 연준·거시 핵심 기사 포함, 무관 기사 감소 |
| 실적일 신뢰성 | Nasdaq와 `/fund` 비교 | 불일치 종목이 `mismatch`로 표시됨 |
| 검증 통과 | `build_rows.py` S5 재작성 횟수 | 현재 수준 이하(일간 0~1회) |
| 토큰 | 정가 환산 비용 | 일간 $0.87, 주간 $0.88 이하 |

| 항목 | 내용 | 대응 |
|---|---|---|
