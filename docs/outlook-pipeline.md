# 전망 리포트 파이프라인 전환 계획

일간·주간 전망 리포트를 "LLM이 수집·계산·작성을 모두 하는 방식"에서 "코드가 수집·계산·검증하고 LLM은 해석만 하는 방식"으로 전환한다.

- 작성일: 2026-11-09
- 상태: 계획 (구현 전)
- 최우선 목표: 리포트 품질 유지, 결과의 신뢰성(수치 정확도, 형식, 기록 성공) 향상

## 1. 제약과 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 과금 | Claude API 키와 추가 과금 없이 claude.ai Pro 구독 안에서 운영 | 사용자 결정 |
| 오케스트레이터 | 기존 Claude 예약 작업(클라우드 세션) 유지 | API 키 없이 LLM 단계를 실행할 수 있는 유일한 경로 |
| 모델 | 기존과 동일 (`claude-sonnet-5-5`) | 사용자 결정 |
| 출력 | 기존 시트 `App_일간전망`, `App_전망` (헤더·열 규칙 불변) | 앱 파서와 화면을 바꾸지 않기 위해 |
| Google Keep, Calendar | 범위 제외 | 사용자 결정 |
| 결정적 단계 위치 | 레포 `ops/outlook/` 의 Python 스크립트 (표준 라이브러리만) | 아래 1-1 참고 |

### 1-1. 스크립트 위치 선정

| 후보 | 판단 |
|---|---|
| 레포 `ops/outlook/` (Python, 표준 라이브러리) | **채택.** 버전 관리와 PR 리뷰가 되고, 로컬에서 같은 입력으로 재현 테스트가 된다. 예약 세션이 레포를 받아 그대로 실행한다. 의존성 설치가 없어 실행 실패 요인이 적다. |
| Apps Script (메인 시트) | 제외. 예약 세션에서 호출하려면 토큰이 필요한데, Apps Script 웹 앱은 요청 헤더를 읽지 못해 환경 secret(헤더 주입)을 쓸 수 없다. 토큰을 평문 환경 변수에 둘 수밖에 없어 보안 규칙에 맞지 않는다. |
| Cloudflare Worker 확장 | 제외. 시세 수집은 이미 Worker를 데이터원으로 쓰므로 충분하다. 뉴스·검증 로직까지 Worker에 넣으면 배포가 늘고 로컬 재현이 어렵다. |

시트 읽기·쓰기는 Google Sheets 커넥터를 계속 쓴다. 비밀값이 필요 없고 현재 검증된 경로다. 대신 쓰기 결과를 다시 읽어 스크립트로 대조해 결정적 검증을 추가한다.

## 2. 목표 구조

```
[예약 작업: 평일 07:00 일간 / 월 06:30 주간, Sonnet 5.5, 전용 클라우드 환경]
│
├── S0 입력 읽기 (커넥터)
│   시트에서 보유·관심 종목, 최근 신호, 최근 주간 전망을 읽어 work/input.json 저장
│
├── S1 시세 수집 (결정적)            ops/outlook/collect_market.py
│   Worker /chart, /fund 호출 → 수치 파싱·등락률 계산·교차 검증 → work/market.json
│
├── S2 뉴스 수집 (준결정적)          ops/outlook/collect_news.py
│   Google News RSS → 중복 제거·최신순 → ID(N1..) 부여 → work/news.json
│
├── S3 보완 조사 (LLM, 제한적)
│   실적 발표일·경제지표 일정 등 S1·S2로 얻지 못한 정성 정보만 웹 검색
│   결과는 ID(W1..)와 URL로 work/extra_sources.json 에 기록
│
├── S4 해석 작성 (LLM)
│   market.json·news.json·extra_sources.json 만 근거로 work/analysis.json 작성
│   수치는 입력 값만 인용, 출처는 ID로만 지정
│
├── S5 검증·행 조립 (결정적)         ops/outlook/build_rows.py
│   스키마·허용값·수치·출처 ID 검사 → 결정적 필드 결합 → work/rows.json
│   실패 시 오류 목록 출력, S4 재작성 1회 → 그래도 실패하면 기록 중단
│
├── S6 기록 (커넥터)
│   기존 규칙대로 오늘 행 교체, 보관 기간 지난 행 삭제, rows.json 그대로 추가
│
└── S7 기록 검증 (결정적)            ops/outlook/verify_written.py
    시트를 다시 읽어 work/readback.json 저장 → rows.json 과 대조
    불일치 시 S6 재시도 (최대 2회) → 실패하면 실패 내용을 보고
```

현재 대비 달라지는 점:

- 수치(지수, 선물, 등락률, 이동평균, 고저점)는 코드가 계산한다. LLM은 수치를 만들지 않는다.
- 출처 URL은 코드가 수집한 목록에서 ID로만 고른다. LLM이 URL을 직접 쓰지 않으므로 존재하지 않는 출처가 들어가지 않는다.
- 야간선물 행의 전망 등급처럼 규칙으로 정해지는 값은 코드가 산출한다.
- 기록 성공 여부를 다시 읽어 코드로 확인한다.
- 품질 유지를 위해 웹 검색은 남기되, 용도를 정성 정보 보완(S3)으로 한정한다.

## 3. 실행 환경

### 3-1. 전용 클라우드 환경

현재 `Default` 환경은 네트워크가 제한 모드이고 허용 호스트가 없어, 컨테이너 안의 스크립트가 외부를 호출하지 못한다. 전용 개인 환경을 새로 만든다.

| 항목 | 값 |
|---|---|
| 이름 | `stock-journal-outlook` |
| 범위 | personal |
| 네트워크 | limited, package registry 허용 |
| 허용 호스트 | `sj-chart.blueinwhite.workers.dev`, `news.google.com` |
| 허용 호스트 (조건부) | 레포를 세션에 붙일 수 없을 때 `github.com` / 야간선물 출처를 직접 수집할 때 해당 사이트 호스트 |
| 환경 변수 | 없음 |
| 비밀값 | 없음 |
| 설정 스크립트 | 없음 (표준 라이브러리만 사용) |

`Default`를 수정하지 않는 이유: 모든 세션에 적용되기 때문이다.

### 3-2. 예약 작업

- 기존 두 예약 작업은 병행 비교 기간 동안 그대로 둔다.
- 새 예약 작업 두 개(v2)를 전용 환경으로 만든다. 모델, 커넥터(Google Sheets), 스케줄은 기존과 같게 둔다.
- 세션에서 레포 스크립트를 쓸 수 있어야 한다. 예약 작업 생성 도구에는 레포 지정 항목이 없으므로 P0에서 다음 순서로 확인한다.
  1. 환경에 레포를 연결해 세션 시작 시 체크아웃되는지 확인
  2. 안 되면 세션 첫 단계에서 공개 레포를 `git clone --depth 1` (허용 호스트에 `github.com` 추가)

## 4. 데이터 계약

### 4-1. `work/input.json` (S0, 커넥터로 읽어 LLM이 저장)

```json
{
  "date": "2026-11-10",
  "mode": "daily",
  "holdings": [{"ticker": "KRX:005930", "name": "삼성전자", "market": "KR"}],
  "watch": [{"ticker": "NASDAQ:MU", "name": "마이크론", "market": "US"}],
  "signals": [{"date": "2026-11-07", "ticker": "KRX:005930", "strategy": "추세추종", "signal": "매도·경계"}],
  "weekly": [{"ticker": "", "name": "시장 전체", "s": "중립", "m": "약강세", "l": "강세"}]
}
```

- 보유 수량·금액은 넣지 않는다. 스크립트와 검색어에 개인 정보가 흘러가지 않게 한다.
- S1과 S5 스크립트가 이 파일을 다시 검증한다(티커 형식, 중복, 보유와 관심 중복 시 보유 우선).

### 4-2. `work/market.json` (S1)

| 구분 | 내용 | 출처 |
|---|---|---|
| 지수·환율·금리 | 코스피 `^KS11`, 코스닥 `^KQ11`, S&P 500 `^GSPC`, 나스닥 100 `^NDX`, 필라델피아 반도체 `^SOX`, VIX `^VIX`, 원/달러 `KRW=X`, 미 10년물 `^TNX` | Worker `/chart?r=1d` (최신가), `r=1y` (일봉) |
| 미국 지수선물 | `ES=F`, `NQ=F` 최신가, 직전 종가 대비 등락률, 시세 시각 | Worker `/chart?r=1d` |
| 코스피200 야간선물 | 마감가, 직전 주간 종가, 등락률, 시각 | 공식 API 없음. 4-5 참고 |
| 종목 | 최신가, 전일 대비, 20·60·200일선과 위치, 20일 고가·저가, 52주 고저 | Worker `/chart?r=1y` |
| 종목 재무 (주간) | 추정 PER·EPS, 목표주가 등 Worker가 주는 값 | Worker `/fund` |

각 값은 다음 형태로 저장한다.

```json
{"id": "M12", "sym": "^SOX", "label": "필라델피아 반도체", "value": 5012.3, "prev": 4950.1,
 "chg_pct": 1.26, "as_of": "2026-11-10T06:00:00+09:00", "status": "ok", "checks": []}
```

- `chg_pct`는 스크립트가 `value / prev - 1`로 직접 계산한다.
- `status`: `ok`, `stale`(시세 시각이 기대 거래 세션보다 오래됨), `mismatch`(출처 표시값과 계산값 차이 0.3%p 초과), `unavailable`.
- 종목 티커는 시트 형식(`KRX:005930`, `NASDAQ:MU`)을 앱과 같은 규칙으로 Yahoo 심볼로 바꾼다.
- 레버리지·인버스 ETF는 기초자산 심볼도 함께 수집한다(예: SOXL → `^SOX`). 매핑표는 `ops/outlook/config.json`에 둔다.

### 4-3. `work/news.json` (S2)

```json
{"id": "N7", "scope": "KRX:005930", "title": "...", "source": "연합뉴스",
 "url": "https://...", "published": "2026-11-10T05:12:00+09:00"}
```

- 시장: 국내·해외 각 5건. 종목: 종목당 최대 3건(종목명과 티커로 검색).
- 일간은 최근 24시간, 주간은 최근 14일만 남긴다.
- URL 기준 중복 제거, 같은 제목의 다른 매체는 1건만 남긴다.
- Google News RSS 링크가 리다이렉트 주소이면 원문 주소로 풀 수 있는지 P2에서 확인한다. 못 풀면 리다이렉트 주소를 그대로 쓴다.

### 4-4. `work/analysis.json` (S4, LLM 출력)

```json
{
  "rows": [
    {"key": "market", "outlook": "약강세", "summary": "...", "checkpoint": "...",
     "nums": ["M3", "M12"], "src": ["N2", "W1"]},
    {"key": "KRX:005930", "outlook": "중립", "summary": "...", "checkpoint": "...",
     "nums": ["T5"], "src": ["N7"]}
  ]
}
```

- 주간은 `outlook` 대신 `s`, `m`, `l`(단기·중기·장기)을 쓰고, `checkpoint` 대신 `event`를 쓴다.
- `summary`, `checkpoint`에 들어가는 숫자는 `nums`에 적은 ID의 값이어야 한다.
- `src`는 `news.json`, `extra_sources.json`의 ID만 쓸 수 있다.
- 야간선물 행은 LLM이 쓰지 않는다. S5가 규칙으로 만든다.

### 4-5. 코스피200 야간선물

공식 공개 API가 없어 완전한 결정적 수집은 불가능하다. 아래 순서로 처리하고, 어느 단계에서 얻었는지 `as_of`, `source`에 남긴다.

1. P0에서 후보 출처(현재 프롬프트의 참고 사이트)를 스크립트로 파싱할 수 있는지 확인한다. 가능하면 S1에서 수집하고 직전 주간 종가와 등락률을 직접 계산해 표시값과 대조한다.
2. 불가능하면 S3에서 LLM이 검색으로 마감가와 직전 주간 종가를 찾아 `extra_sources.json`에 기록하고, S5가 등락률을 다시 계산해 대조한다.
3. 둘 다 실패하면 현행 규칙대로 요약에 `확인 못 함`, 전망은 `중립`으로 둔다.

등급 규칙(현행 유지, S5가 산출): +1.5% 이상 `강세`, +0.5% 이상 `약강세`, -0.5% 초과 +0.5% 미만 `중립`, -1.5% 초과 -0.5% 이하 `약약세`, -1.5% 이하 `약세`.

### 4-6. `work/rows.json` (S5)

시트 헤더와 같은 열 순서의 2차원 배열이다.

- 일간 `App_일간전망`: 작성일, 구분, 티커, 종목명, 오늘 전망, 요약, 체크포인트, 출처
- 주간 `App_전망`: 작성일, 구분, 티커, 종목명, 단기, 중기, 장기, 요약, 근거·이벤트, 출처

작성일, 구분, 티커, 종목명, 출처 URL은 S5가 입력 파일에서 채운다. 행 순서도 현행 규칙(시장 전체, 야간선물, 보유, 관심)대로 S5가 정한다.

## 5. 검증 규칙 (S5, S7)

| 검사 | 규칙 | 실패 시 |
|---|---|---|
| 스키마 | 필수 키, 타입, 행 누락(input의 모든 종목이 있어야 함) | S4 재작성 |
| 허용값 | 전망 값은 `강세`, `약강세`, `중립`, `약약세`, `약세`만 | S4 재작성 |
| 수치 | 본문의 숫자를 추출해 `nums` ID 값과 반올림 허용 범위 안에서 일치하는지 확인. 날짜·시각·기간 표현은 제외 | S4 재작성 |
| 출처 | `src` ID가 존재하고 행당 일간 1~2개, 주간 1~3개 | S4 재작성 |
| 길이 | 요약 일간 1~2문장, 주간 2~3문장 (문장 수와 글자 수 상한) | S4 재작성 |
| 금지 표현 | 확정적 매수·매도 권유 표현 목록 | S4 재작성 |
| 상태 반영 | `status`가 `ok`가 아닌 값을 인용하면 본문에 `확인 못 함` 또는 기준 시각 표기가 있어야 함 | S4 재작성 |
| 기록 대조 (S7) | 시트에서 다시 읽은 오늘 행이 `rows.json`과 행 수, 셀 값 모두 일치 | S6 재시도 |

- 재작성은 1회, 기록 재시도는 2회로 제한한다.
- 최종 실패 시 시트에는 쓰지 않거나(S5 실패) 쓴 행을 원래대로 지우고(S7 실패), 실패 단계와 원인을 예약 작업 결과로 남긴다. 푸시 알림은 기존 설정을 따른다.
- 스크립트의 종료 코드로 다음 단계 진행 여부를 판단한다(0 통과, 1 재작성 필요, 2 중단).

## 6. 레포 구성

```
ops/outlook/
├── README.md              실행 방법, 데이터 계약 요약, 로컬 재현 방법
├── config.json            지수 목록, 기초자산 매핑, 뉴스 쿼리, 보관 기간, 허용값
├── common.py              HTTP(재시도·타임아웃), 심볼 변환, 시간대(Asia/Seoul) 처리
├── collect_market.py      S1
├── collect_news.py        S2
├── build_rows.py          S5
├── verify_written.py      S7
├── prompts/
│   ├── daily.md           v2 일간 예약 작업 프롬프트 원본
│   └── weekly.md          v2 주간 예약 작업 프롬프트 원본
└── tests/
    ├── fixtures/          Worker·RSS 응답 샘플, analysis 정상·오류 샘플
    └── test_*.py          unittest (네트워크 없이 실행)
```

- 예약 작업 프롬프트의 원본은 `prompts/`에 두고, 바꿀 때 PR을 거친 뒤 예약 작업에 반영한다.
- 작업 파일은 세션의 임시 디렉터리 `work/`에만 쓰고 커밋하지 않는다(`.gitignore`에 추가).
- CI는 기존대로 `csp` 체크만 유지한다. 테스트는 로컬과 예약 세션에서 실행한다.

## 7. 단계별 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P0 환경·경로 검증 | 전용 환경 생성. 그 환경에서 테스트 세션을 열어 Worker, RSS 호출과 레포 접근 방식 확인. 야간선물 후보 출처의 파싱 가능 여부 확인 | 세 경로 모두 성공, 레포 접근 방식 확정 |
| P1 시세 수집 | `collect_market.py`, `config.json`, 단위 테스트 | 고정 입력에서 기대 JSON 생성, 실제 실행에서 모든 지수 `ok` 또는 사유 있는 상태값 |
| P2 뉴스 수집 | `collect_news.py`, 단위 테스트 | 시장·종목별 건수, 중복 제거, 기간 필터 통과 |
| P3 검증·행 조립 | `build_rows.py`, `verify_written.py`, 정상·오류 샘플 테스트 | 5장의 모든 검사가 샘플로 재현됨 |
| P4 프롬프트 v2 | `prompts/daily.md`, `prompts/weekly.md` 작성. S0~S7 순서, 종료 코드 처리, 웹 검색 용도 제한, 출력 형식 명시 | 수동 실행 1회씩 성공 |
| P5 병행 운영 | v2 예약 작업을 `App_일간전망_v2`, `App_전망_v2`에 기록. 일간 10거래일, 주간 3회 | 8장 전환 기준 충족 |
| P6 전환 | v2가 기존 시트에 쓰도록 프롬프트 변경, 기존 예약 작업 비활성화(삭제하지 않음), `_v2` 시트 정리 | 전환 후 첫 일간·주간 정상 기록 |
| P7 문서 | README, `AGENTS.md`의 참고 문서, 이 문서의 상태 갱신 | PR merge |

각 단계는 별도 브랜치와 PR로 진행한다. 시트에 새 시트(`_v2`)를 만드는 작업과 P6의 전환은 merge 전에 SJ에게 확인받는다.

## 8. 병행 비교와 전환 기준

같은 날짜의 기존 리포트와 v2 리포트를 비교한다.

| 지표 | 측정 방법 | 전환 기준 |
|---|---|---|
| 수치 오류 | 리포트의 수치를 공식 종가·마감가와 대조 | v2 0건 |
| 형식 위반 | 허용값, 열 개수, 행 누락 | v2 0건 |
| 필수 정보 누락 | 실적 발표일, 주요 일정, 출처 | 기존 이하 |
| 실행 실패 | 예약 작업 실패, 최종 중단 | v2 0건 |
| 품질 평가 | 같은 날짜 두 리포트를 구분 표시 없이 SJ가 평가 | 기존과 같거나 우세 |

기준에 못 미치면 원인별로 조정하고 비교 기간을 연장한다.

- 정보 부족: 뉴스 건수나 S3 검색 범위 확대
- 수치 오류: 수집·변환 규칙 수정
- 품질 평가 열세: 프롬프트 조정

## 9. 롤백

- 기존 예약 작업은 P6 이후에도 비활성 상태로 보관한다. 문제가 생기면 다시 활성화하고 v2를 비활성화한다.
- 출력 시트 구조가 같으므로 앱 변경과 롤백은 필요 없다.

## 10. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| Yahoo 비공식 API 변경·차단 | S1 실패 | Worker 한 곳만 고치면 된다(앱과 공용). 실패 값은 `unavailable`로 표시하고 리포트는 계속 작성 |
| 야간선물 출처 불안정 | 야간선물 행 품질 저하 | 4-5의 3단계 처리, 현행 `확인 못 함`, `중립` 규칙 유지 |
| LLM이 프롬프트 순서를 건너뜀 | 검증 누락 | 종료 코드 확인을 프롬프트에 명시, S7 결과가 없으면 성공으로 보고하지 않게 지시. 병행 기간에 실행 기록으로 점검 |
| S3 웹 검색 출처의 신뢰성 | 근거 품질 | S3는 일정·실적 같은 정성 정보로 한정, 수치 인용 금지. 출처 URL은 검색 결과에서만 기록 |
| 구독 사용 한도 | 실행 실패 | 수집·계산을 코드로 옮겨 세션의 토큰 사용이 현재보다 줄어드는 방향. 병행 기간에는 실행이 두 배이므로 한도를 점검 |
| 예약 세션의 레포 접근 방식 미확정 | 구현 지연 | P0에서 먼저 확정 |

## 11. 보안

- 증권사 키, 계좌, 보유 수량·금액은 스크립트 입력과 검색어에 넣지 않는다.
- 새 환경에는 비밀값과 환경 변수를 두지 않는다. 시트 접근은 커넥터 인증을 쓴다.
- 스크립트는 조회(GET)만 하며 Worker의 공개 엔드포인트와 RSS 외의 외부 호출은 없다.
